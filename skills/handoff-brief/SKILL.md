# Handoff brief

## When to Use
- Use when handing work to another agent or a person, so the receiver can finish without asking anything.

The receiver has none of your context. The brief must stand alone.

## Template
```
Goal: <one sentence: the outcome, not the activity>
Cycle: <path to the cycle folder; read its summary.md first>
Context: <only what the receiver needs; link files, don't paste them. Name the repos it may open; others stay out>
Constraints: <must / must not; scope limits; deadlines>
Success criteria: <checkable items; quality-gate will test these>
Report back: per `three-line-report`, with a link to the result and the leftover count
```

## Deliver
- Send the brief to the receiver's own persona or session. Can't reach it? Give the human the brief to paste there.
- Never carry out your own brief, and never give one receiver two agents' roles.

## Rules
- Write the success criteria so each is yes or no.
- Name files and repos by path. No "the thing we discussed".
- Include anything irreversible that needs approval, and say who approves.
- No secrets in the brief. Point to where credentials are managed instead.
- One brief, one receiver, one goal. Split anything bigger.
